# QuantOS V1-T2 Evaluation Core

V1-T2 adds one deterministic historical application clock around the existing production path:

`completed candle -> Feature Engine -> caller-supplied Alpha -> Risk -> order intent -> Paper Execution -> account/ledger -> metrics`

The evaluator revalidates canonical one-minute sequences, exposes only completed causal features to Alpha, and processes simultaneous symbols in frozen BTCUSDT then ETHUSDT order. Risk and Execution are reused unchanged. Execution remains the only owner of balances, positions, fills, and ledger state.

Metrics use one marked-equity observation after each historical event timestamp. Returns are `equity[t] / equity[t-1] - 1`; the first observation has no return and is omitted. Initial equity still anchors total profit and drawdown, including first-event costs. Sharpe uses the population mean and population standard deviation. Sortino uses `sqrt(sum(min(return, 0)^2) / N)` over **all** N returns, including nonnegative observations as zeros. Both use `sqrt(365 * 24 * 60)` annualization by default (explicitly configurable) for the one-minute 24/7 series. Fewer than two returns, zero standard deviation, or zero downside deviation yields finite zero and names the ratio in `undefined_metrics`. Evaluation arithmetic uses the same fixed precision-34 Decimal context as V1-T1, independent of ambient settings.

Net profit is final marked equity less initial marked equity. Drawdown is the largest peak-to-trough fraction including initial equity. Exposure is the arithmetic mean of gross marked Spot exposure divided by contemporaneous equity: each one-minute observation has equal weight, including warm-up observations within the evaluation interval. A completed trade is a filled SELL: gross PnL uses Execution's weighted-average entry price, entry fees accumulate across BUYs and are allocated in proportion to sold quantity, and exit fees are subtracted once. A full exit consumes and clears all remaining entry fees without division-rounding residue. Expected value and average trade are intentionally identical: mean completed net trade PnL. Win rate is the positive-net-trade fraction; profit factor is summed positive net PnL divided by absolute summed negative net PnL. No completed trades marks expected value, average trade and win rate undefined; no losing completed trades marks profit factor undefined. Undefined values are finite zero with their names in `undefined_metrics`. Fees and slippage are summed from V1-T1 `ExecutionResult` evidence.

Walk-forward validation gives the caller only the earlier fixed training window, then evaluates the returned Alpha callback on the immediately following unseen window through the same runner. Folds advance by the configured minute step; overlapping validation windows are rejected. Boundaries come solely from `WalkForwardConfig`; a base backtest config with conflicting interval bounds is rejected. Each fold starts from the same independent flat reference account. Aggregate Sharpe/Sortino use pooled within-fold returns with no synthetic return across fold resets. Expected value, average trade, profit factor and win rate use pooled completed SELL PnLs. Profit, fees and slippage are summed; exposure is weighted by observation count. Aggregate maximum drawdown is explicitly the **worst individual fold drawdown**, not continuous-account drawdown. `aggregation_semantics` labels these conventions. The evaluator does not average fold ratios or pretend folds are one compounded account, and never promotes a strategy.

Monte Carlo uses a seeded stationary bootstrap of observed causal marked-equity returns. Each simulation starts at a uniformly sampled observed index, continues to the next index with probability `1 - 1/mean_block_length`, and restarts at a uniformly sampled index with probability `1/mean_block_length`. Continuation wraps circularly at the observed series end. Each simulation samples exactly the source return count and compounds from the report's explicit initial equity. It reports terminal return/PnL, maximum drawdown, empirical lower-tail PnL at sorted index `floor((simulations-1)*lower_tail_fraction)`, and positive-outcome fraction. Run identities include datasets and content, code/configuration, strategy/model/feature versions, explicit Alpha implementation identity, windows, seed where applicable, result evidence, and ledger identity. Filesystem paths, logging destinations, callable representation and wall-clock values are excluded. Each historical run requires a fresh ledger.

Inputs retain their original timestamps and ordering. Candle opens must align to UTC minutes, closes must lie in the final millisecond through the exact next-minute boundary, and all supplied closes must share a consistent one-minute grid. Mixed close conventions or gaps in the merged clock fail explicitly instead of being normalized into misleading one-minute return observations. Per-symbol chronology and continuity are checked before merging valid streams. Initial account timestamps cannot be in the future; stale owned-position marks fail closed. At a shared timestamp both market states are installed before BTC then ETH decisions; each decision reads the latest Execution snapshot. UTC day-start equity uses the causal pre-decision marked state, and Risk peak equity observes pre/post-decision marks as they occur.

The selected Alpha later plugs in through `AlphaDecisionFunction`; each call returns an `AlphaDecision`, explicit gross expected edge, and optional volatility. Historical runs start flat because the current snapshot contract has no entry-fee history for a carried position; accepting one would understate realized trade costs. This phase does not select a strategy, fit a model, define promotion thresholds, run continuous paper trading, or enable live trading. The inherited paper fill remains an immediate full fill at the current candle close moved adversely by configured slippage, with the configured quote fee; it does not model liquidity, queues, partial order fills, or next-candle execution.
