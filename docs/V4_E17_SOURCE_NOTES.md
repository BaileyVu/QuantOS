# E17 source integration note

## Source behavior

- Announcement source in `delist_signal.py`: unauthenticated Binance CMS catalog 161 endpoint `https://www.binance.com/bapi/composite/v1/public/cms/article/list/query?type=1&catalogId=161&pageNo=1&pageSize=20`; intended poll every 30s. It reads `data.catalogs[].articles[]`, using integer `releaseDate` (Unix milliseconds), `title`, and optional `code`. Keep the CMS `releaseDate` as the authoritative event time; the live signal window is `0 <= now_ms-release_ms <= 300000`. Parse titles beginning exactly `Binance Will Delist`; body is after “Delist” and before “ on ”; split ticker list on comma/“and”. Deduplicate `(release_ms,ticker)`.
- Study/prereg live entry proxy: 1m bar open for the bar beginning at `floor_minute(releaseDate)+5 minutes`; skip if that bar has zero volume. Spec says live market short filled within 5 minutes of release, else skip; this does not define a precise order placement instant beyond the latency deadline. Exit is 4h after entry (paper spec); prereg’s historical proxy exits at close of the 1m bar ending entry + 240m. Emergency stop +25% above short entry. Risk 2% equity to stop, 1% for first 20 live trades; 3x isolated; cap 5 concurrent / 8 entries per day. For the V4 strategy library, user explicitly narrows eligibility to a USDC-margined perp; require a live USDⓈ-M exchangeInfo contract with `status=TRADING`, `contractType=PERPETUAL`, `quoteAsset=USDC`, and match the listed ticker to `XUSDC` or `1000XUSDC`. If none, log `SKIPPED_NO_USDC_PERP`. The supplied E17 module itself only seeks `XUSDT` / `1000XUSDT` and its `perp_symbols` contract does not enforce traded-previous-day or volume; implement V4 USDC gate separately and explicitly enforce previous UTC day's positive traded volume (source does not pin a volume threshold).
